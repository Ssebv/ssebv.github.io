Odoo RAG: a docs assistant I can measure

An assistant that answers only from the Odoo 19 developer docs and my migration notes, cites its sources, and says so when it does not know. The part I care about most is the evaluation: every retrieval change is measured instead of assumed.

Source code on GitHub →

How it works

  1. Question
  2. Translate if Spanish
  3. Vector + keyword search
  4. Rank fusion
  5. llama3.2
  6. Cited answer or NOT_IN_DOCS

It runs on PostgreSQL with pgvector and local Ollama models, over 341 chunks from 14 documents. There are no API keys and no per-call cost. The trade-off is speed: a median of about 20 seconds per answer on a laptop.

Replay of a real run, shortened. The first question is in Spanish; the docs are in English. The second is out of scope, so the assistant refuses.

The numbers

I compared four retrieval modes on 45 hand-written questions, 35 in English and 10 in Spanish. Recall@5 is how often the right passage appears in the top five results.

Recall@5, all questions
Keyword73%
Vector67%
Hybrid73%
Hybrid + translation82%
Recall@5, Spanish questions
Keyword40%
Vector20%
Hybrid50%
Hybrid + translation90%

The surprise was where the gain came from. Hybrid search alone did not beat keyword search on Recall@5. Translating the question did: Spanish went from 50% to 90%, and English stayed at 80%.

On 20 in-scope and 8 out-of-scope questions, 90% of answers contained the expected terms, 80% had valid citations, none was wrongly refused, and 7 of 8 out-of-scope questions were refused.

What it still gets wrong

  • A wrong answer on a key question. Asked how to stop a data file from overwriting records users edited, it answers forcecreate. The right answer is noupdate.
  • One refusal it should have made. It answered a question about the 2022 World Cup.
  • The evaluation has limits too. I wrote the questions against this same corpus, so the numbers compare modes and do not predict performance elsewhere. The citation metric checks that a cited excerpt exists, not that it supports the claim.

Both failures are recorded in the results file, so any future change has to prove it fixes them.
